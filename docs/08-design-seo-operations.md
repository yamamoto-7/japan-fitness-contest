# デザイン・SEO・運用方針

## 1. デザインコンセプト

- 黒を基調に、赤・白・ゴールドをアクセントとして使用する
- フィットネス大会のステージ、照明、緊張感を想起させる
- スポーツメディアとして、日程と大会名の読みやすさを優先する
- AI生成のヒーロー画像を利用可能とする

配色はブランドカラー確定後にデザイントークン化します。ゴールドや赤は小さい本文文字へ多用せず、コントラストを検証します。

## 2. UI原則

- 開催日、団体、大会名を情報階層の上位に置く
- CTAは「大会を探す」「公式サイトを見る」など動作が分かる文言にする
- 公開・非公開、成功・警告・エラーを色とテキストの両方で示す
- 同じ操作には全画面で同じラベルと見た目を使う
- 削除などの危険な操作を通常操作から視覚的に分離する
- ローディング、空状態、エラー状態を各画面に用意する

## 3. 画像・権利

- AI生成画像でも生成サービスの商用利用条件を確認する
- 実在団体のロゴ、選手写真、大会写真を許可なく利用しない
- 画像には適切な代替テキストを設定する
- ヒーロー画像上の文字にはオーバーレイ等で可読性を確保する
- 生成画像が実在団体の公式素材と誤認されないようにする

## 4. SEO要件

- 日本語の `title` と `description`
- canonical URL、OGP、X向けメタデータ
- `sitemap.xml`、`robots.txt`
- 適切な見出し構造と内部リンク
- HTMLの `lang="ja"`

Next.js App RouterのMetadata APIと、`sitemap.ts`、`robots.ts`、`opengraph-image`規約を利用する設計です。

### ページ別タイトル案

| Page | Title案 |
| --- | --- |
| トップ | `Japan Fitness Contest｜フィットネス大会情報` |
| カレンダー | `大会カレンダー｜Japan Fitness Contest` |
| 大会詳細 | `{大会名}｜{開催日}｜Japan Fitness Contest` |

### 構造化データ

- 大会詳細はSchema.orgのEventを候補とする
- `name`、`startDate`、`endDate`、`location`、`url` を正確なデータから生成する
- オンライン・中止・延期等が必要になった時点でイベント状態のDB項目を追加する
- 表示していない情報や確認できない情報を構造化データだけに含めない

### インデックス制御

- 公開ページだけをサイトマップに含める
- 管理画面とAPIをサイトマップから除外する
- 管理画面は認証で保護し、`noindex` も設定する
- Preview環境は検索エンジンへインデックスさせない
- 非公開大会のURLをサイトマップやOGPへ出さない

## 5. コンテンツ運用

1. 大会名、団体名、開催日、開催地を公式情報と照合する
2. 公式URLが正しいことを確認する
3. 説明文に推測や未確認情報が混ざっていないことを確認する
4. 非公開で保存してプレビューする
5. 誤字、リンク、モバイル表示を確認する
6. 公開する

開催日変更や中止の情報モデルは元要件にありません。必要になる可能性が高いため、Phase 1開始前に `status` 項目追加の要否を決定します。

## 6. 免責・プライバシー

- 非公式であり、各団体・大会運営とは関係がないことを明示する
- 最新・正確な情報は公式サイトで確認するよう案内する
- 外部リンク先の内容を保証しない旨を必要に応じ記載する
- アクセス解析、広告、Cookie導入時にプライバシーポリシーと同意要件を確認する
- 問い合わせ窓口と訂正依頼の手順を公開前に決める

## 7. 収益化ロードマップ

| Phase | 内容 |
| --- | --- |
| 1 | SEO、Googleインデックス、基礎コンテンツ蓄積 |
| 2 | Google AdSense、Amazon・楽天アフィリエイト、ブログ |
| 3 | ジム紹介、スポンサー掲載、独自ドメイン |

広告・アフィリエイト導入時は広告であることを明示し、表示速度、プライバシー、各サービス規約への影響を評価します。

## 8. 定期運用

| 頻度 | 作業 |
| --- | --- |
| 大会情報更新時 | 公式情報照合、登録・レビュー、公開後確認 |
| 週次 | リンク切れ、直近大会、エラーログの確認 |
| 月次 | 古い情報、Search Console、無料枠利用量、依存更新の確認 |
| リリース時 | スモークテスト、サイトマップ、robots、構造化データ確認 |
| 障害時 | 影響範囲、暫定対応、復旧、原因、再発防止を記録 |
