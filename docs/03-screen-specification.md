# 画面構成・画面仕様

## 1. 画面一覧

| ID | 画面 | URL案 | 認証 |
| --- | --- | --- | --- |
| PUB-01 | トップ | `/` | 不要 |
| PUB-02 | 大会カレンダー | `/events` | 不要 |
| PUB-03 | 大会詳細 | `/events/[id]` | 不要 |
| SYS-01 | 404 | 任意の未存在URL | 不要 |
| ADM-01 | 管理者ログイン | `/admin/login` | 不要 |
| ADM-02 | ダッシュボード | `/admin` | 必要 |
| ADM-03 | 大会一覧 | `/admin/events` | 必要 |
| ADM-04 | 大会登録 | `/admin/events/new` | 必要 |
| ADM-05 | 大会編集 | `/admin/events/[id]/edit` | 必要 |

大会詳細の識別子は元資料に合わせて `id` とします。SEOを優先してslugを導入する場合はAPI・DBと合わせて変更します。

## 2. 画面遷移

```text
トップ ──→ 大会カレンダー ──→ 大会詳細 ──→ 公式サイト
  └──────────────────→ 大会詳細

管理者ログイン ──→ ダッシュボード ──→ 大会一覧
                                         ├──→ 大会登録
                                         └──→ 大会編集 ──→ 削除確認
```

未認証で管理画面へアクセスした場合は、ログイン後に元の管理画面へ戻せるようリダイレクト先を保持します。認証済みでログイン画面へアクセスした場合はダッシュボードへ移動します。

## 3. 共通レイアウト

### 公開側

- ヘッダー: サイト名またはロゴ、トップ、大会カレンダーへのナビゲーション
- メイン: 各ページ固有コンテンツ
- フッター: 非公式サイト表記、公式情報確認の注意、著作権表記
- スマートフォンではナビゲーションを省スペース表示にする

### 管理側

- ヘッダー: 管理画面名、ログイン中の管理者名、ログアウト
- ナビゲーション: ダッシュボード、大会一覧、大会登録
- 公開側と誤認しない管理画面用の外観を採用する

## 4. 公開画面仕様

### 4.1 トップ

表示順の案:

1. ヒーロービジュアル、キャッチコピー
2. 「大会を探す」ボタン
3. 直近の大会（開催日、団体、大会名、開催地）
4. 今月の大会数、団体別大会数
5. 更新情報（更新日、大会名、詳細導線）
6. 非公式サイトである旨の注意

状態:

- 大会なし: 「現在公開中の大会情報はありません」と表示する
- 読み込み失敗: 再試行できる案内を表示する
- 画像なし・失敗: 文字の可読性を保つ背景へフォールバックする

### 4.2 大会カレンダー

- 月単位で表示し、前月・次月・当月へ移動できる
- 表示中の年月を見出しとして読み上げ可能にする
- 団体フィルターは Phase 1 案として単一選択＋「すべて」とする
- 開催期間が複数日にまたがる大会は該当する全日に表示する
- 日付選択時は同一ページ内の一覧またはダイアログで大会を表示する
- 大会名の選択で詳細へ移動する
- URLクエリ案: `?month=2026-08&organization=JBBF`

アクセシビリティ上、カレンダーだけでなく表示月の大会一覧も併記することを推奨します。

### 4.3 大会詳細

- 大会名、団体、開催期間、開催地
- 説明・注意事項、公式URLへのボタン
- 大会一覧へ戻る導線、情報更新日
- 非公式情報であり、最新情報は公式サイトを確認する旨

公式URLが未登録の場合はボタンを表示しません。非公開または存在しないIDは404画面を返します。

## 5. 管理画面仕様

### 5.1 ログイン

- メールアドレス、パスワード、ログインボタン
- 認証失敗時は、メールアドレスの存在有無を推測できない共通メッセージを表示する
- 送信中は二重送信を防止する

### 5.2 ダッシュボード

- 全大会数、公開中件数、非公開件数、今後開催される大会数
- 最近更新した大会
- 大会登録、大会一覧への導線

### 5.3 大会一覧

- 表示列: 大会名、団体、開催期間、開催地、公開状態、更新日時、操作
- 初期実装でもページネーションを行う
- 操作: 編集、公開状態変更、削除
- 空状態、読み込み中、取得失敗を明示する

### 5.4 大会登録・編集

入力項目は [02-requirements.md](./02-requirements.md) の「大会入力項目」に従います。

- 保存、キャンセルを表示する
- 登録時の公開状態は非公開を既定値とする
- クライアント側とサーバー側の両方で入力検証する
- 保存成功後は大会一覧へ移動し、完了メッセージを表示する
- 保存失敗時は入力内容を保持する
- 編集中の同時更新制御は Phase 1 対象外

### 5.5 削除確認

- 対象大会名と、削除が元に戻せないことを表示する
- 「キャンセル」と「削除する」を明確に分ける
- API成功後のみ一覧から除去する

## 6. レスポンシブ方針

| 画面幅 | 方針 |
| --- | --- |
| モバイル | 1カラム。表はカード化または横スクロール。操作領域を十分に確保 |
| タブレット | 内容に応じ1〜2カラム。カレンダーの可読性を優先 |
| デスクトップ | コンテンツ最大幅を設定し、余白と情報密度を両立 |

ブレークポイントの具体値はTailwind CSSの設定に従い、実装時の表示確認で確定します。
