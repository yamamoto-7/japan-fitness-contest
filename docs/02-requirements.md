# 要件定義

## 1. 機能要件

### 1.1 公開機能

| ID | 要件 | 優先度 |
| --- | --- | --- |
| PUB-01 | トップにサービス概要とカレンダーへの導線を表示する | 必須 |
| PUB-02 | 直近の公開済み大会を開催日順に表示する | 必須 |
| PUB-03 | 今月の大会数と団体別の大会数を表示する | 必須 |
| PUB-04 | 更新情報を表示する | 必須 |
| PUB-05 | 月間カレンダーに公開済み大会を表示する | 必須 |
| PUB-06 | 団体でカレンダー表示を絞り込める | 必須 |
| PUB-07 | 日付を選択すると、その日の大会を確認できる | 必須 |
| PUB-08 | 大会詳細に大会名、団体、開催日、開催地、公式URL、説明・注意事項を表示する | 必須 |
| PUB-09 | 存在しない、または非公開の大会詳細は404として扱う | 必須 |

「直近」「更新情報」の件数は未決定です。設計案として各5件を既定値とします。

### 1.2 認証・管理機能

| ID | 要件 | 優先度 |
| --- | --- | --- |
| ADM-01 | 管理者がメールアドレスとパスワードでログインできる | 必須 |
| ADM-02 | 未認証利用者は管理画面・管理APIを利用できない | 必須 |
| ADM-03 | ダッシュボードに大会件数と管理導線を表示する | 必須 |
| ADM-04 | 公開・非公開を含む大会一覧を表示する | 必須 |
| ADM-05 | 大会を新規登録・編集・削除できる | 必須 |
| ADM-06 | 大会の公開・非公開を切り替えられる | 必須 |
| ADM-07 | ログアウトできる | 必須 |
| ADM-08 | 削除前に確認を表示し、誤操作を防ぐ | 必須 |
| ADM-09 | 管理画面で10分間操作がない場合、セッションを失効させ自動ログアウトする | 必須 |
| ADM-10 | 団体を一覧表示し、新規登録・編集・削除できる | 必須 |
| ADM-11 | 大会に使用中の団体は削除できない | 必須 |

Phase 1の管理者は1名固定とし、ログイン用メールアドレスとハッシュ済みパスワードはサーバー側環境変数から取得します。管理者テーブルは作成しません。

### 1.3 大会入力項目

| 項目 | 必須 | 入力規則 |
| --- | --- | --- |
| 大会名 | はい | 1〜200文字 |
| 団体 | はい | `organizations` テーブルへ登録済みの団体から選択 |
| 開始日 | はい | `YYYY-MM-DD` |
| 終了日 | はい | 開始日以降。単日開催は開始日と同日 |
| 開催地 | はい | 1〜255文字 |
| 公式URL | いいえ | `http` または `https` URL |
| 説明・注意事項 | いいえ | 最大10,000文字のプレーンテキストを基本とする |
| 公開状態 | はい | 公開または非公開。新規登録時は非公開 |

文字数は実装のための設計案です。リッチテキストやMarkdown入力は Phase 1 の対象外です。

## 2. ビジネスルール

| ID | ルール |
| --- | --- |
| BR-01 | 公開画面と公開APIは `is_published = true` の大会だけを返す |
| BR-02 | 開始日の昇順、同日の場合は大会名の昇順を基本とする |
| BR-03 | 単日開催でも終了日を開始日と同じ日付で保存する |
| BR-04 | 非公開大会へ直接アクセスしても内容を開示しない |
| BR-05 | 管理APIのすべての操作でサーバー側の認証確認を行う |
| BR-06 | 公式URLは外部サイトであることが分かる表示にする |
| BR-07 | 削除は Phase 1 では物理削除案とし、監査要件発生時に再検討する |

## 3. 非機能要件

### ユーザビリティ・アクセシビリティ

- 幅320px程度のスマートフォンからPCまでレイアウトを崩さない
- キーボードのみで主要操作を完了できる
- フォームのラベル、エラー、フォーカス状態を視認できる
- 色だけに依存して公開状態やエラーを伝えない
- 日付は公開画面では日本語表記、APIではISO 8601形式を使用する

### 性能・可用性

- 公開ページはサーバー描画を基本とする
- 一覧APIはページネーションし、無制限取得を避ける
- 外部公式サイトの障害が本サイトの表示を妨げない構成とする
- 無料枠の制限を監視する

具体的なSLAや応答時間目標は、利用規模が不明なため Phase 1 開始時点では設定しません。

### セキュリティ

- パスワードを平文で保存しない
- セッションCookieには本番環境で `Secure`、`HttpOnly`、適切な `SameSite` を設定する
- 管理者の操作がある間だけセッションを更新し、最終操作から10分でサーバー・クライアント双方から失効させる
- 入力値をZod等でサーバー側検証する
- 管理画面の表示制御だけでなく、データアクセス層とAPIでも認可する
- SQLはORMまたはパラメータ化クエリを利用する
- エラーやログにパスワード、ハッシュ、接続文字列を含めない
- 本番シークレットをGitへコミットしない
- ログイン試行回数制限は公開前に方式を決定する

### 保守性・品質

- TypeScriptの型チェック、ESLint、ビルドをマージ条件とする
- APIの検証スキーマとDB定義の不整合をテストする
- 公開・非公開境界と管理API認証を重点的に自動テストする
- 仕様変更と関連文書を同じプルリクエストで更新する

## 4. Phase 1 受け入れ条件

- 公開済み大会だけがトップとカレンダーに表示される
- 団体フィルターにより対象大会だけへ絞り込める
- 日付選択から大会詳細へ遷移できる
- 管理者がログイン、ログアウトできる
- 必須項目不足や不正な日付・URLでは保存されず、入力箇所にエラーが表示される
- 新規大会は非公開で保存され、公開切替後に公開画面へ表示される
- 編集内容が公開画面へ反映される
- 削除確認をキャンセルした場合はデータが残り、確定した場合のみ削除される
- 未認証の管理APIアクセスは `401`、権限不足は `403` となる
- 非公開または存在しない大会の公開詳細APIは `404` となる
- `npm run lint` と `npm run build` が成功する
